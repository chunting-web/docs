## 一、适用范围与信息权威

本文件是类型2/3生成模式和类型4生成模式唯一共享的备注内容规则。模式文件只规定人物分组、行列写入、签名、公式、样式和输出方式，不得改变本文件的内容口径。

### 1.1 基础来源

- 以人物组E=1行的原始好友备注为底稿。
- 可靠查询或提取字段可以补充E=1缺失信息，也可以纠正E=1中明确过时或错误的事实。
- 工作簿列位置变化时，按表头含义识别字段，不机械依赖固定列号。
- 类型4生成模式中的其他E=2、E=3候选备注仅作为辅助来源；只有与E=1和可靠查询字段一致时才能采用，不能单独作为纠错依据。

### 1.2 查询状态与其他说明

以下内容属于查询状态、对象性质、调查过程或评价，通常不得写入最终备注：

- 查不到；
- 未查到；
- 无公开信息；
- 无需查询；
- 公职人员；
- 公办高校；
- 调查过程、证据描述和评价性文字。

`缴未`、`国未`、`央未`、`缴无`、`国无`、`央无`等状态默认不写。只有工作簿或用户明确要求保留状态时才写。

删除资本状态前，先拆分与其连写的有效信息；只删除状态本身，不得连带删除出生年份等内容。`到未YY`和`缴未YY`按5.1的专门规则处理。

查询字段仅写状态时，不视为与E=1冲突，也不得据此删除E=1中已有且无其他冲突的有效信息。例如E=1有EMBA、查询字段仅写“查不到”时，保留EMBA。

“其他情况说明”类字段只用于辅助理解和发现异常。除非内容明确符合备注结构且对人物识别必要，否则不自动写入备注。

### 1.3 同名人物和冲突

- 不得把不同人物组中的同名人物跨身份合并。
- 查询结果如果导致姓名对应的单位、职务、地域或履历整体变成另一位同名人物，不视为可靠纠错，列入待确认清单。
- 查询字段之间互相冲突时，不自行选择看似更新的结果，列入待确认清单。
- 可靠纠错必须能够确认仍是同一个人，并且字段含义、来源和单位明确。

### 1.4 外部核实

未经用户明确授权，不联网搜索，也不使用豆包、百度等工具添加表外信息。

用户授权外部核实时，来源不明、与表内信息冲突或无法确认属于本人的结果不得直接写入备注，应列入待确认清单。

## 二、备注结构与通用清洗

### 2.1 总体结构

按以下总体顺序组织：

`姓名丨有效特殊标识丨现单位现职务+出生日期+资本/市值+持股+个人资产+主营/专业方向+第二职务或社会身份丨曾任单位职务丨添加的群/认识或介绍的人丨毕业院校丨工作地点+籍贯出生地丨省钦群或其他允许保留的省级群`

缺失模块直接省略，不留下连续分隔符。

### 2.2 分隔符、空格和标点

- 使用汉字分隔符`丨`分隔主要模块，不使用竖线`|`。
- 同一主要模块内不得再用`丨`拆分同类信息；多个现任职务、社会身份或曾任职务在各自模块内用空格衔接。
- 现任职务、出生日期、资本或市值、持股和个人资产之间不加空格。
- 持股或最后一个财务字段之后加一个空格，再写主营或专业方向、其他现任职务和社会身份。
- 除资产金额中的半角逗号和模块分隔符`丨`外，通常不加其他标点。
- 确需使用标点时优先使用半角。
- 删除不必要的空格、换行、重复标点和重复信息。
- 同一省份、单位、职务、身份或信息不得重复备注。

### 2.3 管理标签

以下独立管理标签必须删除：

- `不加`；
- `巨超100`；
- `中高100`；
- 企业规模档位、职务档位与`100`组合形成的同类内部管理标签；
- `鲁钦和`；
- 仅用于好友管理、没有退休语义的独立`退`。

以下智能群或省智群标记统一删除：

- `京智十九`；
- `疆智十`；
- `鲁智十六`；
- `黔智十七`；
- `京智群二`；
- 同类`京智`、`疆智`、`鲁智`、`黔智`及其他智能群、省智群标记。

普通重要群、校友群、介绍人和认识的人可以按识别价值保留。不得因删除标签后仍有字数余量而恢复已停用标签；应利用释放的字数保留更高价值信息。

### 2.4 “退”的语义

- 明确是好友管理标签时删除。
- 原备注、查询字段或职务上下文明示“退休”“已退休”时，保留退休语义并统一写`退休`。
- 无法判断时列入待确认清单，不机械删除，也不机械改成退休。
- 不得误删正常身份、单位或词语中的“退”，例如`退役军人`、`退役军人事务部`、`退休干部`。

### 2.5 简称与事实保护

- 不改变单位、职务、身份、地区、资本或学历含义。
- 只使用表内已有或项目明确认可的简称。
- 不以“公认简称”为由自行创造缩写。
- `律协`、`董秘`、`高副总裁`等简称只有在表内已有或用户明确确认进入项目简称白名单后才能使用。

## 三、整合版与精简版

### 3.1 整合版

整合版最多50字，按Excel `LEN`口径计算；汉字、数字、字母、空格、`丨`和标点均计入。

生成步骤：

1. 读取E=1底稿；
2. 逐项核对可靠查询字段；
3. 纠正明确过时或错误信息；
4. 补入可靠且有识别或联系价值的信息；
5. 先按字段规则拆分`到未YY`、`缴未YY`等复合信息，再删除不保留的资本状态、管理标签、智能群、省智群、单位名称中的`有限`和无价值的`持0`；
6. 保留有效个性化信息；
7. 按规定结构生成单行备注；
8. 清除重复和冗余；
9. 在50字内继续补入能容纳的院校、学历、地点、主营或专业方向、重要曾任和有效群等信息。

50字是上限，不是精简目标。不得使用旧操作文档中的1至10列表作为机械删除顺序；目标是在不超过50字的前提下尽量保留全部可靠有效信息。

单位名称已经完整表达主营方向时，可以删除与单位名称完全重复的主营内容；不得因此删除仍有新增识别价值的专业或业务关键词。

### 3.2 精简版启动条件

- 整合版不超过32字：不生成精简版，不复制整合版。
- 整合版为33-50字：保留整合版，并从已纠错整合版生成不超过26字的精简版。
- 原始生成结果超过50字：先删除重复和低价值内容，将整合版压缩到50字以内，再制作精简版。

精简版不得从旧E=1重新生成。

### 3.3 精简版8级优先级

数字越小越重要，按1至8依次保留：

1. 姓名、单位、职务、出生日期；
2. 实缴资本或市值、持股比例；
3. 工作地点；
4. 毕业院校；
5. 主营方向或专业方向；
6. 曾经单位及职务；
7. 添加的群、认识或介绍的人；
8. 籍贯、出生地。

只有以上1至8级，不自行补充第9、10级。

### 3.4 精简算法

- 依次装入第1、2、3……级信息，只要不超过26字，就继续保留能够完整表达的有效信息。
- 超长时按第8、7、6……级顺序删除或压缩。
- 不得为了保留低优先级内容而删除高优先级内容。
- 某一级没有可靠信息时跳过，继续下一级。
- 所有允许保留的群和介绍人统一归入第7级，不提高某类群的优先级。
- 工作地点、毕业院校、主营或专业方向有空间时不得无故省略。
- 完整地点组合能够放入时，不得只保留其中一个省份简称。
- 同一级信息取舍时，优先保留与王市长明确有交集的信息。
- 籍贯和出生地虽然是第8级，也不是默认删除项。
- 第1级本身超长时，先用项目认可的简称压缩单位和职务；仍无法在26字内无歧义表达时，列入待确认清单。

26字也是上限，不是越短越好。低于26字且仍有可靠高优先级信息能够完整放入时，必须继续补入。

删除管理标签、智能群、`有限`、`持0`等无价值内容后，应重新计算字数，并利用释放的空间恢复能够容纳的高优先级信息。

## 四、单位职务与曾任

### 4.1 现任信息排序

- “单位职务”只写实际任职、职称和现任挂职。
- 人大、政协、协会等身份写在社会职务位置，属于现任信息模块，不在社会职务前另加`丨`。
- 将本人担任主要负责人、领取工资或承担主要工作的单位职务放在第一位。
- 再写副职、合伙人，最后写人大、政协、协会和兼职等社会职务。
- 十四届全国人大代表可写`十四全人代`，十四届全国政协委员可写`十四全政委`。
- 经表内信息确认的`援疆六批干部`等社会身份接在现任信息后，不当作群标签。
- 同一单位多个现任职务可以连续书写。
- 同一单位现任负责人此前担任的副职或其他较低职务不再写。
- 公共事务等具有明确职能分工的职位及对应公司应尽量保留。

现任信息内部使用：

`第一现任单位职务YYMM资本/市值持股个人资产 主营/专业方向 其他现任职务 社会身份`

出生日期、资本或市值、持股和个人资产必须紧跟第一现任职务，不得散落在其他现任职务之后。

多个现任单位中，资本或市值属于特定单位时，将该单位职务作为第一现任职，或确保对应财务字段紧跟该单位职务，不得造成资产与单位错配。

### 4.2 单位名称

- 单位名称中的`有限`一律删除，不因字数宽裕而保留。
- `科技发展有限公司`写为`科技发展公司`。
- `股份有限公司`写为`股份公司`。
- `公司`通常保留；名称已有`集团`且省略后不产生歧义时，可以省略`公司`。
- 部、处、室、中心等具有身份识别意义的部门名称不得随意删除。

### 4.3 曾任模块

- 所有已确认的曾任内容合并为一个主要模块。
- 整个曾任模块前只使用一次`丨`。
- 多个曾任单位和职务在模块内部用空格连接，不重复使用`丨`。
- 曾任模块前和模块内容前都不写`曾`；模块位置本身表示曾任。
- 曾任内容不得写成现任。
- 曾任内容原则上控制在10字左右。
- 多个曾任单位时，保留最重要单位以及最高或最重要职务。
- 多个曾任职务级别相近时，优先保留较新任职。
- 政府任职、硅谷等有代表性的经历尽量保留。
- 新疆现任或曾任经历与王市长现任地有明确交集，同级取舍时优先保留。
- 现为同一单位负责人时，不写其在该单位曾任的副职；不同单位的重要经历仍可保留。
- 与某项曾任援疆职务直接相关的批次，与该职务放在同一曾任模块中，不另加`丨`。

## 五、字段格式

### 5.1 出生日期

- 通常使用两位年份加两位月份：`YYMM`。
- 只知道四位年份、不知道月份时，取年份末两位写`YY`，不得补月份。
- 已知可靠具体日期且字数允许时，可以写`YYMMDD`。
- 工作簿或用户明确标识的特殊人物必须写到`YYMMDD`，不得自行判断谁是特殊人物。
- 不写随时间变化的当前年龄。
- 出生日期直接写在第一现任职务后，不加空格。

示例：

- 1972年4月 → `7204`
- 1966年 → `66`
- 1980年10月1日 → 通常写`8010`；允许写日时为`801001`

#### 旧资本状态与出生年份连写

原备注出现`到未YY`或`缴未YY`时，先拆分信息，再清理资本状态：

1. 将`到未`视为`缴未`的旧写法，表示民企实缴资本未查到。
2. 当`到未`或`缴未`后直接紧跟两位数字`YY`时，将其拆分为资本状态和出生年份两个独立字段。`YY`不属于资本金额，不需要再根据资本字段或其他上下文确认其是不是年份。
3. 默认删除`到未`或`缴未`，但保留`YY`；不得把资本状态和出生年份一起删除。
4. 拆分后分别复核出生和资本：
   - 出生字段仅写`查不到`、`未查到`、`无公开信息`等状态时，保留E=1中的`YY`；
   - 可靠出生字段提供相同年份及月份时，按通用规则补充为`YYMM`；提供可靠具体日期且适用时，可以写`YYMMDD`；
   - 可靠出生字段确认E=1年份错误时，以可靠字段纠正；
   - 可靠资本字段提供实际金额时，按5.2格式补入；仅写查询状态时不写资本。
5. 没有可靠月份或日期时只写`YY`，不得补造月份或日期。
6. 只有字符串不符合“完整资本状态后直接紧跟两位数字”的格式、多个可靠出生字段互相冲突、信息疑似属于同名他人或字段含义及来源不明时，才列入待确认清单。

示例：

- `总经理到未75` → `总经理75`
- `总经理缴未75` → `总经理75`
- E=1为`到未75`、出生字段仅写`查不到` → 保留`75`
- E=1为`到未75`、可靠出生字段为1975年4月 → 写`7504`
- E=1为`到未75`、可靠出生字段确认出生于1976年 → 按可靠字段纠正为`76`或相应`YYMM`

### 5.2 企业实缴资本

完全取消“到”字。先统一换算为亿元，再按企业性质使用：

- 民企：`缴`
- 国企：`国`
- 央企：`央`

逗号前表示整数亿元，逗号后表示不足一亿元的金额，固定保留两位并四舍五入。不足1亿元时省略逗号前的`0`。

示例：

- 1亿3000万元 → `缴1,30`
- 7900万元 → `缴,79`
- 252.28万元 → 0.025228亿元 → `缴,03`

无实缴或未查到时存在`缴无`、`缴未`、`国无`、`国未`、`央无`、`央未`等格式，但默认不提取到最终备注，除非工作簿或用户明确要求。

`到未`是`缴未`的旧写法。遇到`到未YY`或`缴未YY`时，必须先按5.1拆出出生年份，再删除资本状态；不得将`YY`解释为资本金额或随状态一起删除。

不得使用`到无`、`到未`、`到国`、`到央`或其他带“到”的资本标识。无法唯一换算时列入待确认清单。

### 5.3 上市公司市值

先统一换算为亿元，再按企业性质使用：

- 民营上市公司：`市`
- 国有上市公司：`国市`
- 央企上市公司：`央市`

格式与实缴资本相同，小数部分固定两位并四舍五入，不足1亿元时省略逗号前的`0`，不得使用“到”。

示例：537,100万元 → 53.71亿元 → `市53,71`

金额或单位不明确时列入待确认清单。

### 5.4 持股比例

- 写在资本或市值之后，格式为`持XX`。
- 百分比四舍五入到整数，不补前导零。
- 45.76% → `持46`
- 9.98% → `持10`
- 4.38% → `持4`
- 100% → `持100`
- 没有持股信息或持股为0时不写；`持0`必须删除。
- 无法判断原值是百分数还是Excel比例值时列入待确认清单。

### 5.5 个人资产和非企业身份

- 可靠个人资产使用`XX万`或`XX亿`。
- 单位或金额不清楚时不写。
- 公职、高校等非企业身份不写企业实缴资本或企业市值。
- 非企业身份存在可靠个人资产信息时仍可写个人资产。

### 5.6 主营或专业方向

- 企业、投资人使用主营方向。
- 协会、专家学者等使用专业方向。
- 压缩后不超过10字，此上限优先于关键词数量。
- 在10字以内且信息充足时，企业主营尽量保留3至5个关键词。
- 单位名称已完整表达主营时，删除完全重复的经营描述。
- 仍有新增识别价值的关键词不得因单位名称相似而全部删除。
- 写在出生日期、资本或市值、持股和个人资产之后，与最后一个财务字段之间留一个空格。
- 整合版和精简版有空间时尽量保留。
- 公职人员字数不足时可以不写主营或专业方向。
- 不改变行业或专业含义。

### 5.7 毕业院校

参考格式：

- `南京大学01本`
- `南京大学01硕`
- `南京大学01博`

规则：

- 同一学校本硕博可以只写一次学校名。
- 信息不全时只写已有信息，不补造年份或学历。
- 不同学校之间使用空格。
- 依次优先保留中青院、北大、国科大或中科院相关信息，其次国外学习经历，再次带入学年份的本科经历。

- 现任单位中出现学校简称，不等于已记录毕业院校；查询字段明确为教育经历时，有空间仍应在院校模块保留。

位置规则：

- 只有一个省级工作地简称、没有城市、籍贯或出生地，且现单位职务未表达同一地点时，将简称放在姓名后、第一现任职务前，写成`姓名丨京单位职务`。
- 单一地点简称与单位职务之间不加空格，也不增加额外`丨`。
- 地点包含省区和城市时，作为完整地点模块放在备注末尾，例如`丨鄂武汉`、`丨冀保定`、`丨川成都`。

- 只知道籍贯或出生地时，只写已有地点并放在末尾。
- 不主动添加`生`字标识出生地，按类型2/3地点组合规则表达。
- 现任信息中另有明确的常驻地或工作地表达，或同一地点模块已经出现时，不重复添加该工作地。

- 籍贯信息不轻易删除；整合版尽量保留，精简版按8级优先级取舍。

## 七、不确定性处理

遇到以下情况，跳过该人物并请求确认：

- 查询或提取字段之间互相冲突；
- 查询结果疑似属于另一位同名人物；
- 无法区分现任和曾任；
- 资本、市值或个人资产单位不明；
- 持股原始数值口径不明；
- 出生日期格式异常；
- 不符合已确认的`到未YY`或`缴未YY`格式，且结合可靠字段后仍无法区分两位数字是出生年份还是其他数值；
- 单位或职务无法无歧义压缩；
- 无法判断“退”是管理标签还是退休语义；
- 无法判断个性化内容类别；
- 精简版无法在26字内保留第1级核心信息；
- 生成模式中工作簿结构、公式或样式与所选模式不一致；审核模式中非样式的结构或公式与所选模式不一致。

待确认清单格式：

`编号｜流水号｜姓名｜问题字段｜E=1原始内容｜查询/候选内容｜具体疑问｜建议处理方式`

确认前不把建议结果写入工作簿。
